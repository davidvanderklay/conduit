Conduit · feature plan

Resume the saved source, and make hold-to-2x unmistakable

When a person returns to an in-progress movie or episode from watch history, Conduit should resolve and play the source they last used without sending them back through source selection. During playback, holding the player should visibly confirm temporary 2x speed in a compact top overlay.

Scope
Server, desktop, Android, iOS
Primary risk
Saved stream URLs can expire or change
Fallback
Source picker remains available

Recommendation

Add a nullable saved-source descriptor to each progress record. Clients resolve the current stream list, match the descriptor, and start the player directly when a match is found. Save a new descriptor whenever the user manually chooses a source or the player successfully starts one.

Important boundary: store source identity, not request headers. Do not persist proxy headers or other credentials. A resolver match should produce a fresh playable URL, which avoids treating an expired signed URL as durable state.

What exists today

The project already synchronizes position and watched state well. The missing piece is the relationship between that progress row and the selected source.

Target experience

01

Tap history

The selected history row includes the media, episode, saved position, and saved source descriptor.

02

Resolve silently

The client fetches current streams for the exact movie or episode in the background.

03

Match and play

A matched playable source opens directly and seeks to the existing position.

04

Fallback clearly

If the source is gone, explain that the saved source is unavailable and show the normal picker.

05

Refresh memory

On a manual selection or successful start, replace the descriptor with the current source identity.

In-progress item

Start at the saved position and use the saved source when available. Do not show source selection before trying the match.

Completed item

The source may still be auto-selected, but preserve the existing completed-item behavior of starting from the beginning unless the user explicitly resumes a position.

Saved-source contract

Use one platform-neutral descriptor in the API. The clients can keep their native stream models, but both must be able to generate and compare the same identity fields.

playbackSource: {
  addonId: string,             // profile-scoped installed add-on ID
  sourceKey: string,            // stable identity, never a raw auth header
  kind: "url" | "torrent" | "other",
  infoHash?: string,
  fileIdx?: string,
  name?: string,
  title?: string,
  filename?: string,
  bingeGroup?: string
}

Matching order

  1. Match a stable torrent identity using infoHash and fileIdx.
  2. Match the exact normalized direct-URL identity for the same add-on.
  3. Use the add-on plus filename, title, and quality traits only as a conservative fallback.
  4. Require a playable URL before opening the player.

Source updates

  • Write the descriptor with the first progress save after a source starts.
  • Write it on pause, close, background, and end saves as well.
  • Do not overwrite a good descriptor with an empty value from a transient player error.
  • Keep old rows valid when playbackSource is absent.
Source identity decision: implement a shared normalization helper and test it against URL query tokens, HLS URLs, torrent file indexes, and add-ons that provide only title or filename metadata. If no stable identity can be produced, fall back rather than guessing.

Server work

Schema

Extend progress without changing its key

Add a nullable JSONB column for the saved-source descriptor and create a forward-only migration. Keep the existing profile and video primary key. This makes the feature additive and keeps all existing progress rows readable.

API

Round-trip the descriptor

Extend the progress PUT body and returned progress item with an optional playbackSource. Validate size, allowed keys, string lengths, and source kind. PATCH watched or dismissed should leave the descriptor untouched.

Portability

Export and import it safely

Include the descriptor in portable profile data, validate it on import, and preserve version 1 compatibility for archives without the field. Do not add stream request headers or secrets to exports.

Tests

Prove the fallback boundary

Cover insert and upsert round trips, omitted descriptors, malformed descriptors, export and import, and responses that contain the descriptor on history, continue, status, and single-item endpoints.

Desktop work

Resume flow

  • Carry the selected progress record, not only its video ID, from history and Continue Watching into the details flow.
  • Resolve the active episode's streams and run the saved-source matcher before rendering the stream rail.
  • Start DesktopPlayer with the matched stream and continue using the existing progress hook for timestamp resume.
  • On a missing or failed match, show the stream rail with a concise “saved source unavailable” message.

Desktop hold-to-2x

  • Add pointer-down, threshold, pointer-up, cancel, and leave-window handling to the desktop player surface and the Electron overlay surface.
  • Set native playback speed to 2 only after the hold threshold. Restore the speed captured before the hold.
  • Expose the current temporary hold state to the overlay so the indicator is visible over native playback.
  • Keep normal click-to-play, seeking, menus, and next-episode controls from firing as a side effect of a hold.

Desktop has two presentation paths: the main native-player controls and the dedicated Electron overlay used above the Linux native surface. The gesture and indicator need one shared behavior contract with platform-specific event wiring.

Mobile work

Resume flow

  • Add playbackSource to the Kotlin progress model and stream source model, including the installed add-on ID needed for matching.
  • When history provides a video ID, load that episode's streams without immediately opening the source page.
  • Play the matched source directly. Only open the source page when the record is legacy, unmatched, unplayable, or explicitly opened through “choose another stream.”
  • Persist the selected source in the existing 15-second, close, background, and end progress saves.

Android and iOS indicator

  • Keep the existing 450 ms threshold and prior-speed restoration.
  • Add a platform callback such as onTemporarySpeedChanged(Boolean) to the shared native player contract.
  • Render a compact top-centered Conduit overlay from the common playback screen while the hold is active.
  • Use the same text and visual treatment on Android and iOS, and announce the state for accessibility.

2x feedback design

Use an in-player overlay rather than a platform Toast. It stays attached to the video, looks like Conduit, and works the same when controls are hidden or the device is in landscape.

» 2× speedRelease to return to normal
  • Position it near the top center, below the safe-area or title region.
  • Show it only after the hold threshold is crossed, not on every short tap.
  • Keep it visible for the duration of the hold and remove it immediately on release or cancellation.
  • Use black, white, and the existing amber accent. Avoid a system Toast, bright green, or an unrelated material style.
  • For mouse and touch, support pointer cancellation and window exit so 2x cannot remain stuck.

Acceptance criteria

01An in-progress movie opened from desktop history starts from its saved position and automatically uses its saved source when that source is returned by the add-on.
02An in-progress series episode opened from Continue Watching or history selects the saved episode and source without opening source selection first.
03The same records work after switching between desktop and mobile, and a client that does not understand the new field still plays using the existing flow.
04If the saved source is gone, expired, or not playable, the user sees a clear fallback message and can choose another source. The app never silently chooses a different provider as if it were the saved one.
05After choosing a replacement source, the next return uses that replacement when it is available.
06Holding on Android, iOS, and desktop changes playback to 2x only after the threshold, displays the top overlay, and restores the previous speed on release.
07Short taps still toggle or reveal controls, double taps still seek where supported, and leaving the player while holding cannot leave playback at 2x.
08Unit, integration, and focused UI tests cover source matching, legacy progress, failed resolution, cross-platform progress payloads, hold threshold, release, cancellation, and overlay visibility.
