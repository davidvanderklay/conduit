Conduit mobile · iOS navigation · postplan

Restore the bec226b2 proportions without faking Liquid Glass

The visual target is the older navigation's balance: smaller-looking icons, enough air around each item, and a compact state that feels like the same bar with labels removed. The material should remain Apple-owned. The current problem is that the native bar's optical sizing and the app's compact geometry are both changing at once.

Recommendation: use the native UIKit tab bar path for the surface, reduce the SF Symbol optical size to roughly 21–22pt, keep compact inner breathing room stable, and let the app own only the state transition until the proportions are correct. Start with variant A.

What the code says today

The reference is Compose geometry

In bec226b2, the old phone bar used a 24dp icon, a 4dp icon-to-label gap, 8dp top and 7dp bottom label padding, and 10dp top and bottom padding in compact mode. That is the proportion target, not the material to copy.

The current path is UIKit geometry

The iOS bridge now renders a native UITabBar. The host frame is 87pt expanded and 68pt compact, the image configuration is 24pt with medium scale, and compact vertical margins drop to 2pt. SF Symbols do not have the same optical bounds as the old Compose icons.

Diagnosis: the bar is not simply “too small.” The native surface is being clipped to an app-sized host while the symbol configuration makes the icon visually dominant. Compact mode then removes the label and removes most of the vertical inset, so the four items read as a tight row.

Pick: A is the implementation target. B is the tuning fallback. C should be a separate experiment, because mixing Apple minimize behavior with Compose's adaptiveCompact state can produce two competing owners.

Implementation sequence

  1. Freeze the reference states. Capture the old bec226b2 phone layout at the top of Home and after scrolling. Record the visible shell bounds, icon bounds, horizontal margins, and safe-area distance. Do not compare only the host frame.
  2. Keep the material native. Keep the iOS bar transparent and platform-owned. Do not add a Compose Surface, custom blur, fake refraction, or a second border behind the UIKit bar.
  3. Calibrate optical icon size first. Start at UIImage.SymbolConfiguration(pointSize: 21, weight: .regular, scale: .medium). Try 22pt only if the symbols become visibly smaller than the old 24dp icons. Keep the same configuration in expanded and compact states.
  4. Make compact label-only. Toggle the title to nil, but keep the icon size and vertical inset stable. Change the shell height by about 20pt, not the item scale. Start with 80pt expanded, 60pt compact, and 6pt vertical inner margin.
  5. Preserve the reference width. Keep the compact floating inset near 64pt per side and the expanded inset near 14pt per side. Do not narrow the compact shell further to solve an icon-sizing problem.
  6. Keep one state owner. For this pass, Compose continues to decide compact, classic, and adaptive. If variant C is selected later, remove the manual adaptive state before enabling system minimize behavior.
  7. Test the controller path separately. If the standalone UITabBar still does not produce the expected Liquid Glass behavior on the target OS, prototype the same items inside a transparent UITabBarController. Do not add transforms to compensate for controller layout.

Smallest likely code change

The first pass should touch only the native iOS bar. The bridge and Compose navigation state already provide the right inputs.

1. Use a 21–22pt regular SF Symbol configuration.
2. Keep compact and expanded item insets close to one another.
3. Use a measured 80/60pt host pair, then adjust by 4pt increments.
4. Keep the existing explicit container layout that pins UIKit to SwiftUI bounds.
5. Recheck standalone UITabBar versus UITabBarController only if the material is wrong.

Avoid changing destination order, profile behavior, scroll detection, or the Compose content padding in the sizing pass.

Acceptance checks

  • Expanded and compact use the same perceived icon size. Compact does not make the symbols look larger.
  • The selected item has visible glass separation without a second fake glass layer.
  • There is consistent air above and below compact icons. No icon appears pinned to the shell edge.
  • The compact floating width matches the old reference closely and does not make the four items feel crowded.
  • Scroll down and scroll up animate the shell as one surface. There is no symbol scale jump or horizontal reflow.
  • Classic mode remains full width and keeps safe-area behavior correct.
  • Home, Discover, Library, and Settings remain independently tappable in both states.
  • Verify iPhone portrait, iPhone landscape, iPad portrait, and iPad landscape. Also check iOS 15 fallback behavior since the project deployment target is iOS 15.
  • Test with Reduce Motion enabled. The final layout should remain legible without depending on the transition animation.

Scope

In scope: iOS native bar ownership, shell proportions, SF Symbol optical size, compact spacing, safe-area placement, and the expanded-to-compact transition.

Out of scope: destination changes, profile menus, search behavior, Android navigation, content layout, and a full rewrite around system adaptive tab-bar minimization.
