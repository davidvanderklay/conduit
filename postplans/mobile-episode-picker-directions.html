Conduit · mobile stream selection · UI directions

Make Episodes a real phone surface

The current half-width drawer is too narrow for episode titles and thumbnails. The desktop web flow keeps its existing back-to-episodes control. These two directions only decide how the mobile app should expose episodes from stream selection.

Recommendation: choose A. Use a fullscreen episode modal on phones, and preserve a wider side drawer only on tablet-sized layouts. It fixes the screenshot problem without forcing phones into a cramped desktop composition.

What changes

  • Web and desktop: remove the new Episodes button. Keep the existing Back to series episodes control.
  • Mobile phone: Episodes opens a fullscreen modal with a clear title, season row, wide episode cards, and a close action.
  • Tablet: the same content can use a side drawer because there is enough width for readable copy and artwork.
  • Stream selection remains underneath. Selecting an episode closes the episode surface and loads sources for that episode.

Tablet treatment for A

At tablet widths, the drawer can be wider than the current 52% layout and use two clear columns: a 110 to 140dp thumbnail and the episode title/details. The drawer should never squeeze the copy below a readable minimum.

Acceptance checks

  • On a phone, no episode title wraps into a one-character column.
  • Opening and closing Episodes does not change the selected episode or source state.
  • Selecting an episode closes the modal or drawer and requests sources for that video ID.
  • System Back closes the episode surface first, then follows the existing stream-selection Back behavior.
  • Web and desktop do not show a duplicate Episodes action.
  • Tablet layouts preserve enough room for thumbnail, episode title, and progress text.
